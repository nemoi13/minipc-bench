# MiniPC Bench: сайт на GitHub Pages

Данные лежат в файлах `data/devices.json` (устройства) и `data/brands.json` (производители). Страницы сайта строятся из них сами. Код руками править не нужно.

## Первый запуск
1. Создайте на github.com публичный репозиторий (например `minipc-bench`) и загрузите в него все файлы проекта вместе с папкой `.github`.
2. Settings → Pages → Source: **GitHub Actions**. Через минуту сайт откроется на `https://ВАШ_НИК.github.io/minipc-bench/`.

## Как добавлять и править устройства (админка)
Админка НЕ выкладывается на сайт. Откройте на своём компьютере файл `admin/index.html` из папки проекта (двойной клик). Перед этим один раз выполните `node build.mjs`, чтобы обновился `admin/data.js`; в архиве он уже собран.
1. Вкладка «Подключение»: введите ник, имя репозитория и токен. Токен: GitHub → Settings → Developer settings → Fine-grained tokens, доступ только к этому репозиторию, право Contents: Read and write. Токен хранится только в вашем браузере.
2. «Устройства» → «Добавить устройство» или «Править». В списке видно, сколько данных заполнено и чего не хватает.
3. Бенчмарки: вписывайте цифры или вставьте строки `pm_cpu=10800` в «Быстрый ввод». Пустое поле пропускается. У каждого замера можно отметить «из источника», если цифра не ваша.
4. Ссылки на обзоры добавляются в блоке «Ссылки на обзоры». Фото выбирается файлом и уменьшается автоматически.
5. «Сохранить в список», затем «Опубликовать на сайт». Сайт обновится за минуту.
Без токена админка работает тоже: она скачает `devices.json` и `brands.json`, а вы загрузите их в папку `data/` на GitHub.

## Настройки
- `data/criteria.json`: список бенчмарков (`metrics`), сценарии (школьникам, студентам, NAS…), пороги классов. Новый бенчмарк добавляется одной строкой, он сразу появится в админке, методике и карточках.
- `data/site.json`: email, Telegram, YouTube, текст «О проекте», `siteUrl` для своего домена.

## Сценарии (для школьника, студента, Homelab…)
Все сценарии лежат в `data/criteria.json`, раздел `uses`. У каждого есть название, описание, текст «почему», правила отбора `req` (обязательные), `pref` (желательные) и веса рейтинга `rank`. Для каждого сценария сайт сам создаёт страницу `/ru/for/<ключ>/` со списком подходящих устройств. Чтобы поменять порог (например, ОЗУ для студента с 16 на 8 ГБ), измените число в `req` и опубликуйте файл. Если параметра у устройства нет, оно попадает в блок «мало данных», а не пропадает. В админке есть ручная отметка «Подходит для», она сильнее правил.

## Как считается рейтинг
Баллы 0–100 считаются относительно всей базы и только по тем данным, что есть. Нет замера: параметр пропускается, устройство остаётся в каталоге. «Мощный/слабый» это положение в базе по CPU-тестам, «холодный/горячий» берётся из температуры CPU в стресс-тесте (пороги в `criteria.json`). Мощность берётся из TDP процессора.

## Проверка на компьютере
`node build.mjs` (Node 18+), результат в `dist/`.
